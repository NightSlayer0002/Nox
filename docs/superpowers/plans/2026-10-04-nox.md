# NOX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build the first usable NOX character and a thorough educational walkthrough.

**Architecture:** Browser modules own the face, stage, speech, camera, memory, and interaction. A dependency-free Node server serves the app and an optional structured AI route. A shared packet validator is the boundary between dialogue and actions.

**Tech Stack:** Node 22+, JavaScript ES modules, Canvas 2D, browser media/speech APIs, node:test.

**Spec:** docs/superpowers/specs/2026-10-04-nox-design.md

## Global Constraints

- Node 22 or later. No npm dependencies, no CDN assets, no bundler, no account required for demo.
- Server binds to 127.0.0.1 and never serves .env or workspace files.
- Camera is previewed locally and never sent to the model in this release.
- Both brains produce validated speech/emotion/action/memory packets.
- Silent canvas recording is labelled; live-provider failure is shown rather than silently switching brains.

## Review Focus

1. Corrupt or blocked localStorage must not crash startup: memory tests and browser reload.
2. Unknown action or oversized model speech must never reach the stage: character tests.
3. Malformed, oversized, or cross-origin HTTP bodies must be rejected: server tests.
4. Camera/voice permission denial must leave text interaction usable: browser fallback checks.
5. A scene reset or mode switch must cancel old choreography: browser scene/Escape checks.
